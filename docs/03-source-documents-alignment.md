## 原始方案已明确的业务标准

- AI 承担前端宣发、接待和筛选；人工承担深度开发、商务谈判、签约交付和客户运营。
- A/B/C 分级：A/B 当日移交；招商接收后 24 小时内触达；沙龙结束后 3 个工作日内复盘。
- 表单主数据包括客户信息登记、客户移交和客户跟进记录。
- 对外知识库必须与内部知识隔离；业务变更、FAQ、提示词与黑名单需要留版本。
- 风险策略至少覆盖支付牌照、数字货币资质、保本承诺和法律意见等禁止输出类别；应支持关键词与语义层的检测、拦截和日志。
- 测试覆盖业务主线、知识库召回和隔离、风险拦截、会话审计、多语种、权限、重复线索和异常会话。

## 本项目已确认的裁剪

| 主题 | 正式材料的建议或目标 | 本项目的当前决定 |
| --- | --- | --- |
| 首个渠道 | Shopify 客服中台汇聚网站、WhatsApp、Instagram Messenger、邮件等渠道。 | 先直接接入 Telegram，覆盖群聊和私聊；其他渠道以后续连接器方式加入。 |
| 使用对象 | 覆盖品牌、客服、招商、商务、行政、管理层。 | 先给内部招商团队试用，外部代理和经销商不登录一期系统。 |
| 语言 | 简中、英文、西班牙语、法语。 | 一期仅中文和英文。 |
| AI 分派 | A/B 线索自动生成工单，再由人工复核和流转。 | AI 提出 A/B/C 建议；经理确认后再分配专员。 |
| 自动拉群 | 原始 SOP 写为 AI 自动拉群。 | 以客户同意后的邀请链接或引导加入实现，遵守 Telegram Bot 能力边界。 |
| 日志留存 | 正式材料提出至少 6 年并支持审计导出。 | 先实现完整审计和权限控制；保存期限及地域待业务和合规确认。 |
| API 对接 | 客户库、工单、OA、BOM，以及区块链、硬件、合规 Agent 为二期预留。 | 一期只定义渠道、线索、审计和知识库接口边界，不进行上述系统联调。 |

## 现有中台 Agent 页面参考

CNDT 现有中台的 `/agents` 页面将“AI 宣发官”和“AI 客服官”作为前端标准化工作的两个核心 Agent，并提供提示词与触发逻辑的保存、版本可追溯能力。页面还将区块链、硬件、合规岗位 Agent 标为“API 预埋、待二期建设”，并把客户库、工单系统、OA、BOM 物料库列为一期仅字段定义和权限规划的预埋对接项。

本项目参考这一边界：一期创建可审计的 Agent 配置模型，但只开放 AI 客服官的 Telegram 对外接待；AI 宣发官保留配置和内容审批模型，不承诺自动跨平台分发。二期岗位 Agent 不进入本次 MVP。

## 不能视为既成事实的内容

正式材料中的时长、7x24 秒级响应、全渠道覆盖、日志留存期限和第三方工具能力是方案目标或验收要求。项目文档不得将它们表述为已经上线、已经合规、已经获得平台授权或已经实现的功能。
