# CNDT FDE MVP 交付路线图

## 总体顺序

| 计划 | 可验收产物 | 前置条件 | 覆盖材料 |
| --- | --- | --- | --- |
| P1：基础与 Telegram 线索闭环 | 内部人员可接收 Telegram 入站消息，建立客户/会话/线索，经理确认并分配专员，全程有权限和审计。 | 测试 Bot、内部角色名单、试点群权限。 | 初始架构图、商务成交 SOP、FDE 正式材料。 |
| P2：知识库、AI 客服与风险策略 | 中英文受控问答、知识条目审批、风险拦截、人工接管、提示词与质量追踪。 | P1 的客户、会话、审计和角色模型。 | FDE 技术/管理材料、Agent 页面、硬件产品背景。 |
| P3：视频传媒矩阵 | 原创/授权视频资产、脚本与发布包、审核、活动、专属入口、视频到线索归因与看板。 | P1 的来源、客户和线索模型；P2 的内容审核模型。 | 初始架构图、OK 科技资料、Agent 页面。 |
| P4：运营扩展 | 首个外部视频渠道的官方连接器、聚合指标回流、活动/沙龙与运营复盘。 | P3，且已核验目标平台 API 权限。 | SOP、FDE 方案、视频传媒矩阵设计。 |
| P5：二期连接器 | WhatsApp/Facebook/Instagram、网站客服、CRM/OA/BOM/硬件状态等逐项连接器。 | 每项有独立需求、数据处理和 API 权限评审。 | FDE 技术材料、Agent 页面、产品背景材料。 |

## P1 完成定义

- Telegram 私聊与已授权群聊的入站更新只保存一次，重复 webhook 不产生重复会话或线索。
- 内部经理能查看线索、确认或修改 AI 之外的人工初始分级、分配专员；专员只能看被分配的线索。
- 每一次线索级别变化、分配、内部备注和状态变化都有审计记录。
- 系统只处理用户主动进入 Telegram 后的消息；不发起陌生用户私聊、不自动拉群。
- P1 不调用大模型、不做视频制作和不接入外部内容平台。

## P2 至 P5 的启动闸门

- P2：内容合规负责人交付首版中英文资料目录、外部可见范围和禁答清单。
- P3：确认首批视频平台、内容生产责任人、原创/授权素材来源与落地页/深链接规则。
- P4：取得目标平台的正式开发者权限并完成隐私、内容和频率限制评审。
- P5：每个外部连接器先完成数据字段、失败补偿、审计、权限和下线方案的独立设计。
