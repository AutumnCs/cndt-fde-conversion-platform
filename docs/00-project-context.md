# 项目上下文与已确认共识

最后更新：2026-09-27  
状态：持续更新

## 产品目标

搭建“CNDT 招商 SOP FDE 架构图”对应的内部招商中台，而不是搭建稳定币、DeFi、钱包或 KYC 终端等底层金融系统。

正式材料将 FDE 定义为 Foundation - Do - Evolve，即基础搭建、执行落地、迭代进化。本项目的 MVP 属于 Foundation 阶段：先建立可用、可审计的 AI 接待和人工成交协作闭环，再进入真实业务运行和持续优化。

系统目标是把以下链路产品化：

`Telegram 群聊/私聊接待 → AI 答疑与筛选 → 线索分级 → 经理确认 → 专员承接 → 跟进与成交记录 → 社群/活动运营`

## 一期使用者与职责

| 角色 | 一期职责 |
| --- | --- |
| 内容合规负责人 | 审核、发布和回滚 AI 知识库与对外话术。 |
| 经理 | 查看线索、确认 AI 判断、分配专员、管理成员与数据。 |
| 招商专员 | 承接获分配的高意向客户，维护跟进与成交记录。 |
| 讲师/顾问 | 运营社群内容、答疑、组织沙龙/发布会邀约。 |
| 系统管理员 | 一期由经理兼任，维护渠道配置和基础权限。 |

原始 SOP 还定义了品牌部、客服团队、商务部、行政、部门负责人和总负责人等职责。本项目将先把它们映射为平台角色和审批链，不要求在一期全部独立设岗。

## 已确认的业务规则

- 首批仅供内部团队试用；暂不开放外部代理商或经销商登录。
- 首个正式渠道是 Telegram；一期同时支持群聊和私聊。
- 未来有意接入 WhatsApp、Facebook、Instagram，但不进入一期交付。
- AI 首期支持中文与英文，自动识别语言并允许客户切换。
- AI 仅使用经内容合规负责人审核的中英文资料、FAQ、招商政策和话术。
- 超出知识库、涉及价格/收益/合作承诺或风险话题时，AI 转交人工而不自行承诺。
- 正式材料要求对“支付牌照、数字货币资质、保本承诺、法律意见”等主题实施关键词和语义双重拦截；项目将把它们作为可审计、可版本化的风险策略，而非将任何相关能力或资质视为已经成立。
- 新系统从上线日起接收新线索；一期不迁移历史 CRM、表格或个人聊天记录。
- 正式材料列出中文、英文、西班牙语、法语的多语种目标；本项目已确认一期只交付中文和英文，其余语种留待后续评审。

## 线索模型

| 状态 | 含义 | 系统动作 |
| --- | --- | --- |
| A 类 | 高意向：主动询问合作/代理、价格或方案；留联系方式；预约会议；完成资格问卷等。 | AI 提醒经理，经理确认后分配专员。 |
| B 类 | 有兴趣但尚未准备决策。 | AI 生成培育或移交建议，进入经理确认队列；是否同日移交按最终运营规则配置。 |
| C 类 | 初步了解或仅咨询基础信息。 | 由 AI 和社群内容持续培育。 |
| 无效/风险 | 广告、骚扰、重复线索或需要拦截的内容。 | 不进入招商分配；保留审计记录。 |

正式 SOP 规定 A/B 类当日移交、招商专员在接收后 24 小时内触达；本项目保留这两项作为待验收的运营规则。经理确认的具体时限尚未最终确认。

## 已知渠道边界

- Telegram Bot 不能主动开启陌生用户私聊；用户需要先发起聊天或通过深链接启动。
- 需要群内完整线索识别时，Bot 应为群管理员或关闭 Privacy Mode；具体权限由群管理方确认。
- Telegram 身份以 Telegram 用户 ID 为主；跨渠道合并必须在客户同意并提供可验证联系方式后进行。
- 原始 SOP 所说的“自动拉群”是业务意图。在 Telegram Bot MVP 中，系统只能在客户同意后提供群组邀请链接或引导加入，不能擅自把用户加入群组。
- 原始技术说明提出会话日志留存不少于 6 年。项目先实现不可随意删除、可审计导出的日志能力；实际留存期限、访问范围和数据地域须经业务与合规确认后冻结。
