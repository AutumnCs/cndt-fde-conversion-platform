# 海外获客矩阵参考：能力筛选与合规边界

状态：参考材料已归档；不构成一期需求或实施指令  
最后更新：2026-09-27

## 参考材料与使用原则

`assets/source-materials/OK科技矩阵功能介绍.pdf` 及配套截图展示了一类“海外矩阵运营系统”的功能营销材料。它可帮助团队理解内容生产、渠道分发、线索承接和运营看板应具备的体验，但其中的功能声明、效果数据与“可规避封禁”等说法均未验证，也不应被视为平台授权、合规承诺或产品需求。

本项目只建设面向自有或明确授权账号、基于官方接口和用户同意的获客与转化能力。任何渠道的实际可用功能，以目标平台的书面政策、已获 API 权限和上线前合规评审为准。

## 可借鉴的能力（后续获客模块）

| 能力域 | 可采用的产品能力 | 必要控制 |
| --- | --- | --- |
| 账号与渠道 | 已授权企业账号目录、分组、角色权限、连接状态 | 只连接自有/授权账号；凭证加密、最小权限、可撤销授权。 |
| 内容资产 | 原创或取得授权的素材库、权利/授权期限标记、版本与审批 | 无授权不得发布；保留来源、版权与审批记录。 |
| AI 内容协作 | 文案、图片/视频创意辅助生成、翻译、字幕与格式适配 | 人工审核后发布；不得生成虚假承诺、误导性金融或招商宣传。 |
| 计划发布 | 日历、草稿、审核、定时发布及已发布内容归档 | 仅使用官方允许的发布接口；不支持模拟人工或绕过审核。 |
| 线索承接 | 可追溯短链、UTM、落地页/Telegram 深链接、主动咨询表单 | 明示收集目的并取得同意；进入 CRM 后遵守数据保留和访问控制。 |
| 互动服务 | 对用户主动发来的私信或评论进行受控回复、人工接管 | 不主动骚扰；频率限制、退订/停止触达机制、敏感问题转人工。 |
| 数据分析 | 内容、活动、来源到线索/转化的聚合分析与 A/B 实验 | 优先匿名/聚合统计；不以伪造互动作为指标优化手段。 |

## 不纳入本项目的能力

以下内容即使出现在参考材料中，也不设计、不采购、不运营：

- 批量登录、操控或购买大量第三方账号，设备农场、代理/IP 规避、验证码/风控绕过，或任何“防封号”承诺。
- 自动点赞、关注、评论、刷播放/完播等虚假互动或操纵平台指标。
- 批量私信、群发引流或向未同意的用户发起营销触达。
- 采集、导出或交易竞争对手粉丝、评论者、UID、电话、邮箱等个人资料；所谓“同行截流”。
- 下载、搬运、去水印、混剪他人作品以规避原创、版权或平台审核。
- 绕过内容审核、反爬、平台反滥用规则或地域/账号限制。

## 与 CNDT FDE 招商中台的关系

现阶段的 Telegram MVP 保持不变：先完成 **用户主动进入 Telegram → AI 客服官受控答疑 → 线索分级 → 经理确认 → 专员跟进** 的闭环。

若后续确认建设获客模块，它应服务于该闭环，而不是取代它：

`已授权内容与账号 → 合规审核 → 官方渠道发布 → 可追溯入口/落地页 → 用户自主咨询 → Telegram/CRM 线索闭环`

建议将其作为 Telegram MVP 验收后的“获客模块（候选下一阶段）”。在设计冻结前，需要逐渠道核验 API 能力、账号性质、目标市场、隐私/同意文案、内容版权责任和人工审核责任人。
