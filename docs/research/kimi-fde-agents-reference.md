## 页面可确认的产品结构

- 页面名称为“AI 员工配置”。
- 当前有两个核心 AI 员工：AI 宣发官和 AI 客服官。
- 每个 Agent 的系统提示词和触发逻辑可保存，配置版本应可追溯。
- 同一中台把功能分为：宣发中心、AI 客服工作台、线索池、工单移交、跟进与成交、沙龙运营、知识库与 FAQ、风控与审计、AI 员工配置。
- 二期岗位 Agent 为区块链、硬件和合规，页面明确标为“API 预埋、待二期建设”。
- 客户库、工单系统、OA、BOM 物料库属于一期仅定义字段和权限的预埋对接项，实际联调属于二期。
- 公开页补充了“八步主线漏斗”、渠道矩阵效果、品牌内容源头、沙龙策划/邀约/现场/复盘、成交登记、FAQ 多语种复核、黑名单规则库与会话审计等模块。
- 公开页的全链路包括：前端宣发与获客导流、AI 接待筛选、人工确认移交、招商跟进与成交、活动/沙龙运营和风控审计。

## 对 Telegram MVP 的设计影响

| Agent | 一期状态 | 可配置项 | 不纳入一期 |
| --- | --- | --- | --- |
| AI 客服官 | 对外运行 | 中英文系统提示词、知识库范围、风险策略、A/B/C 分级规则、人工转接规则、Telegram 触发逻辑。 | 自动签约、自动付款、自动分配专员。 |
| AI 宣发官 | 配置保留，不对外自动发布。 | 内容审批状态、渠道模板、触发逻辑版本。 | 多平台自动发布、KOL 投放、广告归因。 |
| 区块链、硬件、合规岗位 Agent | 二期预留。 | 角色模板与接口边界。 | 真实业务执行或外部系统联调。 |

## 必须进入领域模型的配置对象

1. Agent：角色、启用状态、允许渠道、所属团队。
2. PromptVersion：版本号、内容、审批人、生效时间、回滚目标。
3. TriggerPolicy：触发事件、适用渠道、分流条件、人工接管条件。
4. KnowledgeScope：可访问的知识库、语言、外部或内部可见范围。
5. RiskPolicy：黑名单版本、拦截级别、告警对象、审计保留策略。
